Order

A lightweight framework for structuring Roblox games: load any module by name, control how your game starts up, and use the systems most games need without building them first.

Less wiring between modules, and the same startup order on the client and the server every time.

local GetRemote = shared("GetRemote")
local PlayerData = shared("PlayerData")

local CombatService = {}

function CombatService:Init()
    GetRemote("Attack"):OnEvent(function(player)
        PlayerData:IncrementNumValue(player, "Hits", 1)
    end)
end

Why Order?

Spend your time on gameplay instead of plumbing between modules.

Load anything by name

  • Replace require() paths with shared("ModuleName"), or a partial path when two modules share a name.
  • Modules can depend on each other in a cycle. Order resolves them for you.
  • Use modules from other frameworks by pointing their require at shared.
Learn more →

Predictable startup

  • Every task runs a synchronous Prep, then an async Init, on the client and the server.
  • Set a Priority to load a task earlier or later, and choose how init phases run across tasks.
  • Code groups load only the code each place needs, so a lobby and a game server can share one project.
Learn more →

Batteries included

  • Player data saved with ProfileStore and replicated to each client.
  • Networking through GetRemote, and UI panes and buttons with AtomicUI.
  • Developer tools: a Cmdr console, a place switcher, and permissions.
Learn more →

How it works

Write a task, reference other modules by name, and Order initializes everything in order.

Any module in a tasks folder is a task. Order finds it and runs it, so there is no list to keep up to date.

local PlayerService = {
    -- Higher values load first
    Priority = 10,
}

-- Synchronous setup phase
function PlayerService:Prep()
    self.Cache = {}
end

-- Async runtime phase
function PlayerService:Init()
    local DataManager = shared("DataManager")
    DataManager:LoadAll(self.Cache)
end

return PlayerService

Frequently asked questions

What is Order?
Order is a lightweight Luau framework for structuring Roblox games. It loads any module by name with shared(), starts every task in a predictable order on the client and the server, and includes player data, networking, UI and developer tools.
Is Order free and open source?
Yes. Order is open source under the MIT license, and its source code and project template are on GitHub.
Does Order work with Forest and Wally?
Yes. Forest is recommended for new projects, and Wally is still supported. Use one package manager per project.
How does Order load modules?
Call shared("ModuleName") with a module's name, a partial path, or the ModuleScript itself. Modules in a tasks folder are found automatically, and each one runs Prep, then Init, in priority order. Modules can also depend on each other in a cycle.
Is Order used in production?
Yes. Order powers Combat Arena and The Block, and sustained over 800,000 concurrent users with no errors during the Roblox Innovation Awards event in The Block.
